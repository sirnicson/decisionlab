# V2.3.1 — DecisionLab Client Advisory Workspace Lock

Status: **AUTHORITATIVE V2.3.1 AMENDMENT**

This amendment supersedes any earlier learner-facing branding, Command Centre naming, workspace-label wording, Sea Wolf stage-rail layout, Next Site Insight visibility, and Treatment average-summary instructions where they conflict with the rules below. Locked task mechanics, data and scoring remain unchanged.

## 1. Product identity

The learner-facing product identity is now **DECISIONLAB**.

Approved sidebar lock-up:
- native HTML/CSS `D` mark in the established lime accent;
- `DECISION` in the stronger white weight;
- `LAB` in a lighter lime treatment;
- secondary line: `Client Advisory Workspace`.

The old learner-facing `Solve It / READINESS LAB` brand is removed from the application shell. Historical/reference documents may still name the source preparation concept, but the running product must display **DECISIONLAB**.

## 2. Global workspace label

`Client Advisory Workspace` replaces `Independent Preparation Workspace` everywhere in the learner-facing application.

This applies to:
- Home;
- Red Rock;
- Sea Wolf;
- Task 1 Result;
- Task 2 Result;
- persistent topbars and workspace labels.

On Home, the topbar contains the workspace label only. `Fairhaven Environmental Trust · Environmental Recovery Programme` remains engagement-specific context inside the Home engagement content rather than functioning as the application identity.

## 3. Dark sidebar information architecture

The persistent desktop sidebar is:

`DECISIONLAB`
`Client Advisory Workspace`

`Home`
`01 Red Rock Study`
`02 Sea Wolf Study`

Rules:
- remove `Command centre`;
- do not add a standalone `Results` item;
- do not add a separate Learning Path heading between Home and the two workstreams;
- Home is the engagement-entry destination;
- Task results remain attached to the workstream that generated them.

## 4. Red Rock sidebar behaviour

Red Rock retains the V2.2 contextual sidebar approach. Its Investigation / Analysis / Report subnavigation expands under `01 Red Rock Study` when relevant. No separate Red Rock stage rail is restored.

## 5. Sea Wolf sidebar behaviour

Remove the separate white Task 2 stage rail entirely.

When Sea Wolf is active, its current-site stages expand beneath `02 Sea Wolf Study` in the dark sidebar:

- Site Brief
- Characteristics
- Categorisation
- Initial Pool
- Prospect Selection
- Treatment
- Result

`Transfer Review` may appear contextually only when that transient stage is active.

The stage list remains a progress/context treatment and must not create free navigation that bypasses locked task sequencing.

## 6. Sea Wolf workspace composition

Desktop Sea Wolf becomes:

`dark application sidebar | expanded main work canvas | Site Information`

The former four-zone composition with a second white stage-navigation rail is prohibited.

The recovered horizontal space belongs to the main interaction canvas. Keep a compact case/site context line above the main task card showing the selected Sea Wolf study and current site. If a timer is active, it may sit in this compact context line.

## 7. Next Site Insight visibility

`Next Site Insight` is routing intelligence and appears **only during Categorisation**.

It must not appear during:
- Site Brief;
- Transfer Review;
- Characteristics;
- Initial Pool;
- Prospect Selection;
- Treatment;
- Site Result;
- Task 2 Result.

The underlying next-site data and routing logic remain unchanged.

## 8. Treatment decision support

Remove the learner-facing Treatment right-rail summary:
- `Selected trio`;
- `Avg P`;
- `Avg M`;
- `Avg E`.

Do not alter the internal treatment-effectiveness calculation. The scoring engine may continue to use the locked arithmetic logic. The UI should instead direct the learner to judge whether the selected three-microbe portfolio collectively fits:
- Permeability requirements;
- Mobility requirements;
- Energy requirements;
- desired trait;
- undesired-trait constraint.

Treatment instructional copy should not foreground arithmetic averages as the primary decision aid.

## 9. Result architecture

Preserve the V2.2.15 embedded-result rule:
- Red Rock ends in its Task 1 Result/Review while Red Rock remains the associated workstream;
- Sea Wolf ends in its Task 2 Result/Review while Sea Wolf remains the associated workstream;
- no standalone Results route/item is exposed in the sidebar.

Result exit language is `Return Home`, not `Return to Command Centre`.

## 10. Locked mechanics preserved

V2.3.1 does **not** change:
- Red Rock datasets or answer keys;
- Red Rock scoring;
- Sea Wolf fixed decks;
- characteristic-derived initial pools;
- routing rules or expected allocations;
- transfer reassessment mechanics;
- prospect-round mechanics;
- treatment-effectiveness scoring;
- Task 1 / Task 2 weights;
- timer durations;
- persistence/session behaviour;
- Learning Mode / Simulation Mode separation;
- client/scientific case data.

## 11. V2.3.1 visual acceptance criteria

The build passes V2.3.1 review when:
1. the application shell displays **DECISIONLAB** rather than Solve It / Readiness Lab;
2. `Client Advisory Workspace` replaces `Independent Preparation Workspace` everywhere in the running UI;
3. the sidebar reads `Home → 01 Red Rock Study → 02 Sea Wolf Study`;
4. `Command centre` is absent;
5. Sea Wolf has no white stage-navigation rail;
6. Sea Wolf stages are shown contextually inside the dark sidebar;
7. the Sea Wolf work canvas visibly expands into the recovered width;
8. `Next Site Insight` is present during Categorisation only;
9. Treatment shows no `Selected trio` average block;
10. locked gameplay and scoring tests remain unchanged/passing.
